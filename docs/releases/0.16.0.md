## sail 0.16.0 (pre-release)

A pre-release: configuration fields, the C ABI and the Swift and Kotlin
APIs may still change before 1.0. Mostly behaviour brought in line with
sing-box and Mihomo where an app moving from sing-box would notice it.

Documentation: https://peakpassvpn.github.io/sail/

### Breaking changes

- The control API is served on a unix socket (`api.sock` in the data
  directory) unless `api.listen` is set, and `api.listen` now needs a
  `secret`, carried by every call as `Authorization: Bearer`; it takes
  loopback addresses only. A failed call answers `{"error": {"code",
  "message"}}`; a failed reload answers 400 with why, not 202.
- The old stat pages, HTML and JSON, are removed: the management API's
  `/connections`, `/stats` and `/status` replace them, and the control
  JSON gains users, stats, status and inbounds.
- An inbound with no `listen_port` is a configuration error, unless
  another inbound leads to it, as a detour's.
- The C ABI: `sail_check_config(path, settings, out, err)` takes a new
  `out` before `err`. Unless null, it receives `{"warnings": [...]}`: the
  fields sail ignores, deprecated ones, and what building the
  configuration logged as a warning, as `sail -T` prints them. The Swift
  and Kotlin packages do not call it, and are unchanged by this.

### DNS

- `dns.reverse_mapping` keeps the answers sail gives itself, a hijacked
  query's included, as sing-box does: a connection to the bare address is
  routed by its name.
- A query that carries its own EDNS (a cookie, padding, the DO bit) is no
  longer answered from the cache, as sing-box decides it: clients that
  check cookies (c-ares, dig) no longer drop cached answers. A cached
  answer keeps the question as the client wrote it.
- New server type `sequential` (a sail extension): asks its servers one
  after another, the next only when one gives no answer, within a budget,
  then SERVFAIL. See the reference.
- Each query logs a line at debug: what answered it, its code, TTL and
  time.

### Routing and groups

- `override_destination` is a route option (route, route-options and
  sniff rules) and takes effect when the connection is dialled, as in
  sing-box: the rules keep matching the address, so a LAN or private
  address rule after a sniff still holds, and a proxy is sent the sniffed
  domain, or else the name sail's DNS gave for the address. `true` or
  `"proxy"` gives the name to proxies; `"proxy_and_direct"` to a direct
  dial too, resolved by its own `domain_resolver`. A Clash configuration's
  sniffer keeps Mihomo's override at the sniff.
- A route rule with an action and no conditions is taken, matching
  everything, as sing-box takes it.
- `resolve` hands its addresses to every outbound, and takes the
  destination's domain.
- A fallback group leaves a member whose server is unreachable at once,
  counts failures, can be pinned from a dashboard, and shows its state
  (Mihomo's). A Clash url-test pauses after an interval unused.
- A failed connection's log names the group member it went through.

### Inbounds and others

- An HTTP proxy keeps the `Host` its client sent, as sing-box forwards it;
  a 407 names the inbound's own realm.
- TUN fields that change nothing where they are set are warned of, not
  refused; `auto_route` in a network namespace of its own leaves the
  host's DNS alone.
- `sail check` prints its warnings; errors keep their causes; local
  rule-set files are followed as they change; `log.redact`.
- A connection's `host`, in the control API, the C ABI and the Swift and
  Kotlin models, now gives the name it was dialled by before the sniffed
  one; new fields `sniff_host` and `dial_domain_source` (`sniff` or
  `reverse_mapping`) say where it came from. The Clash API shows them as
  `sniffHost` and `dialDomainSource`, and its `dnsMode` is `mapping` where
  the name came from the DNS answers sail gave, as Mihomo's.
- The management API takes a unix socket or a secret, and serves users,
  traffic, status and connections. `GET /api/v1/runtime/events` streams
  what happens to users as Server-Sent Events: `shut` (over its quota or
  past its expiry, and disconnected) and `removed` (taken out of an
  inbound), with `lagged` and how many were missed when a subscriber falls
  behind.

### Builds and tooling

- sail builds for `mipsel-unknown-linux-musl` (with a nightly and
  `-Zbuild-std`); there is no mipsel file in this release yet.
- `scripts/netem`, the weak-network test bench, uses a pair of namespaces
  of its own for each run, takes a shaped scenario of one's own
  (`--shape`), and pins the client's CPU per workload.

macOS now ships a file for each architecture, not one universal file.
This release is the first in which two things are verified: the DNS cache
fix with c-ares clients (the dig half was verified before), and the macOS
x86_64 package.

The Windows zip carries Wintun's `wintun.dll` (0.14.1, amd64), unmodified
from wintun.net under its own license, `wintun-LICENSE.txt`. Nothing is
code-signed yet; every file has a build provenance attestation:

    gh attestation verify sail-0.16.0-x86_64-unknown-linux-musl.tar.gz -R peakpassvpn/sail
