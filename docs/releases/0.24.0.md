## sail 0.24.0 (pre-release)

A minor release on top of 0.23.0. Servers and routers hold back
connections that have not authenticated when memory runs short or their
handshake places fill. A host that embeds sail knows each session by the
number its connection records carry, and its domain; matches sessions
against sing-box rule-sets; changes and enforces a user's limits without
a reload; and can read every connection record without losing one. Apart
from the breaking changes below, the C ABI and the Swift and Kotlin APIs
only gain.

**The weak-network throughput figures of 0.23.0 stay preliminary.** The
full cold re-run of the weak-network suite is still under way; its
figures come in 0.25.0's notes.

Documentation: https://peakpassvpn.github.io/sail/

### Breaking changes

- **`Sessions::tcp` and `Sessions::udp` return the session's number**
  (sail#13): `Result<u64, Refused>`, where they returned
  `Result<(), Refused>`. A caller that only tests for the error compiles
  as it is.
- **`user::Limits` is `#[non_exhaustive]`**, and it and
  `config::UserLimits` have a field more, `max_tcp_connections`: build
  them from `Default::default()` and set the fields wanted.

### Embedding

- **A host limits and disconnects a user without a reload** (sail#14's
  R1-d): `Instance::set_user_limits`, `set_users_limits` for many under
  one lock, `restore_user_limits` back to the configuration's, and
  `disconnect_user`, which closes a user's live connections and says how
  many. Limits set for a user no inbound has yet wait for it.

- **A host knows its sessions by number, and their domains**: the number
  `Sessions::tcp` and `udp` return is the session's connection records'
  `id`, and a host outbound gets it as `SessionInfo::id`, before the
  session is counted. Each number a host is told has one closed record,
  however the session ends: one the rules or an outbound refuse, TCP or
  UDP, has one with nothing sent or received. `SessionInfo::domain` and
  `domain_source` are the domain known for the session and where from, as
  its records tell them: the destination's own, or what a `sniff` rule
  read, for a session to an address.
- **Rule-sets for a host** (sail#16): `sail::embed::RuleSet` reads a
  sing-box headless rule-set, `.srs` or `.json`, from bytes or a path,
  and matches a host's `MatchInput` (network, domain, addresses, port,
  source), or a `SessionInfo`, with the code sail's router uses. A rule
  with a condition a host's input cannot carry is refused as it is read.
- **Lossless connection records** (sail#14's R1-e;
  `Options::connection_records_lossless(cap)`,
  `Instance::connection_records()`): for a host that bills by them, every
  connection record is kept for one reader from the instance's first
  start. Past `cap` queued, records fold into a summary of their user,
  inbound and outbound (`Record::Folded`) that adds up their bytes, so
  what the reader gets adds up to every byte counted, however late it
  reads; no connection waits for it. `Kinds::CONNECTION` stays as it was
  for other subscribers.

### Configuration

- **`user_limits.<name>.max_tcp_connections`** limits a user's live TCP
  connections alone, its UDP sessions not counted; with
  `max_connections` too, both apply. The management API's limits take it
  as well.

### Default changes

- **Servers and routers hold back unauthenticated connections under
  memory pressure** (sail#15): with less memory free than
  `inbound.memory_reserve` (20% of what the system or the cgroup gives),
  or more connections in their handshake than an eighth of the open-file
  limit, an accepted connection first closes the handshakes stalled past
  `inbound.handshake_stall` (3 s), oldest first; on a server, a source
  four of whose handshakes failed in a minute, none succeeding since, is
  refused (`inbound.score_sources`); and with less than half the reserve
  free every new connection is refused. Whatever the memory, an inbound
  whose handshake places (`inbound.max_handshakes`) are all taken closes
  its stalled handshakes the same way, so that a slow-loris cannot hold
  them all: under one at 2000 new connections a second on each of two
  inbounds, a prompt client got in 77 times of 135, against 21 of 146
  without. With 750 MiB of a 1 GiB cgroup taken by another process, sail
  was killed for memory under that flood without admission, and lived
  through it with.
  Hysteria2 and TUIC refuse a new connection before its handshake under
  any pressure, since a QUIC handshake under way cannot be closed.
  Sessions that authenticated are never touched. `GET /admission`,
  `?kinds=admission` on `GET /events`, `Kinds::ADMISSION` and
  `Instance::admission()` tell it. `--set inbound.memory_reserve=0
  inbound.handshake_descriptor_share=0` turns it off. Free memory is read
  on Linux and Android only: elsewhere no memory pressure is seen, and a
  full inbound still closes its stalled handshakes.
