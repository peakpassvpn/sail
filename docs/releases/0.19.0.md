## sail 0.19.0 (pre-release)

A pre-release: configuration fields, the C ABI and the Swift and Kotlin
APIs may still change before 1.0. sail now finds which program opened a
connection itself on Linux and macOS, follows the system's split DNS on
all three systems, and runs a provider's WireGuard proxies. A change of
network closes only the connections it affects. Every fix of 0.18.1 is
here too, marked *(0.18.1)*.

Documentation: https://peakpassvpn.github.io/sail/

### Breaking changes

- **Who opened a connection is looked up only when something needs it.**
  (97dd88a2) The owner (process, user, Android package) is found only
  when a routing or DNS rule, or a rule-set a rule names, matches on it
  (`process_name`, `process_path`, `package_name`, `user`, `user_id`
  and their regex forms), or when `route.find_process` is true, as in
  sing-box. **On Android, the host's `find_connection_owner` is asked
  only then**: before, it was asked for every connection, so the
  connections list always had packages. A host that wants them there
  without such a rule sets `"route": {"find_process": true}`.
- **A change of network closes only the connections it affects.**
  (79d7fbf8) Before, any change of the default interface's state closed
  every connection and every TUN flow.
  - An address added (a new IPv6 /64 after the Wi-Fi comes up) is no
    longer a move: no connection is closed, and no `Event::Network` is
    told.
  - A move closes a connection bound to an interface when that interface
    or its address is gone, and one on the default route when the
    default interface, its index, gateway or kind changed, or its
    address is gone. A connection whose address is not known (UDP)
    counts any address gone as its own.
  - `network_changed` (`sail_network_changed`) within 2 s after
    `set_network_state` is folded into that state: no second move.
  - A wake, or `network_changed` with no state pushed before it, closes
    every connection, as before. A host that relied on `network_changed`
    after a push to close everything calls `close_all_connections`.
  docs/embed.md, *The network*, has the whole rule.
- **The Clash API's `/rules` speaks Mihomo's shape.** (deb0e47a) Each
  rule has Mihomo's `type` (`DomainSuffix`, `IPCIDR`, `RuleSet`, `AND`,
  `OR`, `NOT`, `Match`…), a `payload` as Mihomo nests it, `proxy`,
  `index` and `size`. sing-box's `type` (`default`/`logical`) and the
  `kind`, `payload` and `action` fields sail gave before are gone. A
  connection's `rule` and `rulePayload` are those of the rule it
  matched.
- **A TLS half-close sends close_notify alone.** *(0.18.1)* (2b01623a)
  Shutting down a TLS stream's sending side no longer shuts down the TCP
  connection; the peer closes it first, so sail's side is not left in
  TIME_WAIT.

### Routing

- **sail finds who opened a connection itself.** On Linux (633e51e8)
  through sock_diag and `/proc`, on macOS (403a77f6) through the
  kernel's PCB list and libproc: `process_name`, `process_path`, `user`
  and `user_id` rules match there. `rule-process-name` is a default
  feature now.

### Network changes

- **The connections a move closes** are chosen per connection, above.
  Streams over a pooled carrier (sing-mux, h2mux, smux, AnyTLS, amux,
  Hysteria2/TUIC) record where their carrier went out (28476e5d), and a
  connection through a WireGuard endpoint survives a move, as the
  endpoint binds anew (aa517c7e). Each move logs what of the state
  differed.

### DNS

- **The `local` server follows the system's split DNS.** A name under a
  domain the system sends to its own servers is asked of those servers,
  through the interface they belong to, the longest suffix winning: on
  macOS its supplemental match domains and `/etc/resolver` (d606c44a),
  on Windows the NRPT (c957b610), on Linux systemd-resolved's routing
  and search domains (845ae9cf).

### Clash and Surge configurations

- **Mihomo's `wireguard` proxy is a WireGuard endpoint.** (6c3b95b7)
  `ip`/`ipv6`, one peer or `peers`, `allowed-ips`, `reserved` and
  `persistent-keepalive`; `amnezia-wg-option` is an error.
- **A provider's WireGuard proxies are members it runs.** (0503647c,
  d5c7386b) From a Clash subscription or a Surge policy-path's
  `[WireGuard]` section. A member's tasks are contained: one that fails
  fails that member, never the instance; a retired member stops at once.
- **`sail --managed-update` keeps a managed Surge profile up to date.**
  (7f387e0e) A profile with `#!MANAGED-CONFIG` is fetched again once its
  interval has passed, loaded, put in place and reloaded; one that does
  not load leaves the file as it was. Unlike Surge, a strict profile
  whose update fails is still served.

### Clash API

- **Rules turned off and on, and what dashboards read.** (9046ee4a)
  `PATCH /rules/disable`, with each rule's `disabled`, `hitCount` and
  `hitAt` in `extra`; `/configs` gives `interface-name`, `sniffing`,
  `tun.stack`, `tun.device` and `unified-delay`; a connection's
  metadata gives its process, inbound address, user and uid.
  yacd's and metacubexd's requests are tested (f7499785).

### Protocols

- **TUIC and Hysteria2 clients send ECH**, as sing-box's do (b1b59845).
- **An outbound multiplexes over the grpc transport** (sing-mux over
  gRPC), as sing-box's does (0d57b0c2).
- **Hysteria2 through a Mihomo server**: an upload-first connection no
  longer waits for a response Mihomo sends only with its first data
  (bf9465dd).
- **AnyTLS and mux: a session cut short is not used again**, and a
  stream stuck on a reused session is opened once more on a fresh one.
  *(0.18.1)* (147c177b)
- **A UDP reply from `::1` stays `::1`**, not `0.0.0.1`. *(0.18.1)*
  (9fe3d609)
- The SOCKS inbound reads its handshake in one or two reads, not seven
  (cde97c0f).

### TUN and netstack

- **The app learns at once when sail closes its connection**: a reset
  within a second, for a change of network, the Clash API, a reload's
  recheck or the instance stopping. *(0.18.1)* (161aaf76)
- **Many connections opened at once are not reset under pressure**:
  only stale handshakes are reclaimed, and a reply sets aside a header,
  not a packet. *(0.18.1)* (76bfcdcb)
- **A new SYN on a four-tuple in TIME-WAIT opens a connection**, as in
  Linux (RFC 6191); it used to be answered with the old ACK until
  TIME-WAIT ran out (66783f2b).
- With offload on Linux, each TUN write gives its packet's headers and
  valid checksums, and batches of several flows coalesce: the Trojan TUN
  download cell went from 0.86–0.90 to 0.94–0.95 of sing-box (d6aeb5f0).
- A TUN connection's read takes what follows ahead, within the memory
  budget: router-profile upload over TUN 3766 → 4962 Mbit/s (44df1226).
- The SACK scoreboard is read in one pass instead of quadratically, and
  maps keyed by what arrives from the network hash with foldhash, seeded
  per map (08568927).

### Profiles

- The mobile profile's TCP receive windows grow to 128 KiB, not 64:
  Trojan-over-TUN upload 0.91 → 0.98 of sing-box (5256ccb3).
- The router profile's Hysteria2 stream window is 4 MiB
  (`quic.hysteria2_stream_window`), so streams a client stopped reading
  no longer freeze the others (e0a4a1a8).

### Logging and dialling

- Console lines carry colours only on a terminal, and never with
  `NO_COLOR` (9735c753).
- A WireGuard endpoint's normal stop is no longer logged as an error
  (8ce2cf18).
- The dial fields Windows refuses (`tcp_fast_open`,
  `bind_address_no_port`, `routing_mark`, `protect_path`) say why
  (6d3d1053).

### Builds

- `outbound-vless` builds with only the grpc transport, and a QUIC
  client builds without the server handshake; both feature sets are
  linted in CI (911c0ed9).

### Testing

- An Android emulator job runs sail in a `VpnService`: per-app rules, a
  switch of network, a package rule, and connections sail closes
  ending at the app (869badb9 and after).
- An interop matrix runs every protocol against sing-box 1.14.2 and
  Mihomo 1.19.32, sail as client and as server (18ea848a): 490 of 495
  cells pass, and docs/compat lists the rest with their causes
  (0e08ca40).

### Swift and Android

The Swift package needs SystemConfiguration (declared in its module map).

```swift
.package(url: "https://github.com/peakpassvpn/sail", exact: "0.19.0")
```

```kotlin
dependencies {
    implementation(files("libs/sail-0.19.0.aar"))
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.10.2")
    implementation("org.jetbrains.kotlinx:kotlinx-serialization-json:1.9.0")
}
```
