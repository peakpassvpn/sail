# Internal UDP diagnostics

`internal-diagnostics` exposes the current running dispatcher's typed admission snapshot. Metrics are independent atomic reads; absent or unobserved metrics remain null. `internal-udp-target-diagnostics` additionally enables observation of one host-owned immutable IPv4 endpoint. Both features are absent from defaults.

The host constructs `InternalUdpTargetPolicy::new(SocketAddrV4)` and passes it to the consuming `Options::internal_udp_target_policy` builder before `Instance::new`. Invalid zero ports, unspecified, multicast and broadcast addresses return a static `InvalidArgument` error. The policy has no public getter or serialization and its Debug is redacted. There is no runtime, environment, profile, settings or reload target configuration. The host owns its private endpoint input; it must configure any independent native packet observer from the same immutable input.

The instance fixes its policy across reloads and restarts. Every dispatcher has a fresh epoch and optional sink. Without a policy, no sink, ring or trace is created. The outer snapshot remains schema 1. Its additive `udp_target` child is schema 2, with `fixture` always the public neutral protocol identifier `fixed-ipv4-policy-v1`, and `configured` reporting whether the instance has a policy. This identifier never denotes or encodes an endpoint. An unconfigured snapshot has the current epoch, zero dropped events, no contention and empty events. Configured snapshots can also have zero events; emptiness is no delivery or coverage claim.

Each packet is checked against the exact frozen IPv4 address and port, including NAT reuse and UoT writes. Traces own only their original epoch's sink. Dispatchers reject foreign trace contexts. Reusing an originally unobserved NAT association reports missing original coverage instead of inventing routing or open evidence. Write success means AsyncWrite accepted the encoded frame, not wire delivery or peer receipt. Native header counters remain separate from these SDK observations.

The sink has 16 fixed 512-byte binary slots. Producer and getter use try_lock, with visible dropped and snapshot_contended accounting. Reads do not drain. Events contain only closed numeric enums, numeric fields and booleans, and at most four epoch-hashed opaque hops. They contain no raw address, target, domain, tag, rule text, payload, credential or error text. Export bounds are at most 1024 bytes per event and 16640 bytes per snapshot, including the new schema fields. Feature-off code removes policy, observer state and hooks; allocation controls compare fresh exact baseline and candidate builds under identical flags.

Tests use mock sinks and loopback only. Source compatibility without injecting a policy does not establish configured behavior equivalence. Client wrappers, policy provenance, platform feature forwarding, actual device builds and traffic acceptance require separate exact-source validation. Platform callbacks and the TUN request contract are unchanged.
